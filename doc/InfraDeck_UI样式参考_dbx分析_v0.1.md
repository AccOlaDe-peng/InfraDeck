# InfraDeck UI 样式参考（基于 dbx 界面分析）v0.1

> 状态：讨论稿。来源：dbx（数据库连接工具）截图分析。目的：为 InfraDeck 的界面改版提供一套"高密度、低装饰、功能内聚"的样式基准。
> 关联文档：《InfraDeck_V1.1_产品演进设计》《InfraDeck_系统架构设计》三栏 UX。

---

## 1. dbx 界面总体印象

一句话概括：**单窗口、四层水平分区、零弹窗化、密度优先**。所有功能在常驻区域内完成，按钮全部收敛到"它所作用的区域"的边缘，没有为单个功能单独开窗。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ① 顶部工具栏（全局动作，一行）                                              │
├──────────────────────────────────────────────────────────────────────────┤
│ ② 会话 Tab 栏（每个已打开的连接/查询一个 tab，可关闭）                       │
├──────────┬───────────────────────────────────────────┬───────────────────┤
│          │ ③ 主工作区工具条（作用于当前数据集）         │ ④ AI 助手侧栏      │
│ 左侧资源  │ ┌─────────────────────────────────────┐   │  （对话 + 快捷     │
│ 树（搜索  │ │           数据网格 / 编辑器           │   │   回复 + 上下文    │
│  + 层级  │ │                                     │   │   选择 + 模型）    │
│  树）    │ └─────────────────────────────────────┘   │                   │
│          │ ⑤ 底部状态条（行数/耗时/SQL/翻页/导出）      │                   │
└──────────┴───────────────────────────────────────────┴───────────────────┘
```

## 2. 逐层拆解

### ① 顶部工具栏（全局层）

- **内容**：`新建连接`、`新建查询`、`数据传输`、`驱动管理`、`更多 ▾`，右侧是通知/更新/设置等低频图标。
- **模式**：每项 = 图标 + 短标签，横排一行，高度约 36–40px；低频项全部折叠进 `更多`。
- **要点**：全局层只放"创建类/管理类"动作（跨资源、低频），**不放**任何作用于具体资源的按钮。

### ② 会话 Tab 栏（上下文层）

- 每个打开的连接/查询占一个 tab：`图标 + 名称（user@db 或 query 名）+ × 关闭`。
- tab 上用小圆点表示连接存活状态（绿点 = 已连接）。
- **要点**：多服务器并行操作不用切窗口，上下文切换成本 = 一次点击。Tab 栏同时充当"当前打开了什么"的状态一览。

### ③ 左侧资源树（导航层）

- 顶部一个**常驻搜索框**（过滤树节点，不是全局搜索）。
- 树形结构：`连接 → 数据库 → 表/视图/存储过程/函数/触发器`，每类节点用**不同颜色的实心小图标**区分（表=绿色、视图=蓝色、函数=紫色…）。
- 节点自带元信息：`test200 默认库`、`表 18`（子节点计数）、连接状态点。
- 树节点 hover 才出现操作按钮，平时隐藏——**密度与可操作性并存**。
- **要点**：树是"资源清单"，搜索框保证几百个节点下仍可用；颜色承担分类识别，不承担装饰。

### ③' 主工作区工具条（数据集层）

紧贴数据网格上方，所有按钮只作用于**当前网格**：

- 左：数据集控制下拉（`全部行 ▾`、`WHERE`、`ORDER BY`）。
- 右：`刷新`、`自动`（自动刷新开关）、`跳转列`、`新增行 ▾`、`删除行`、`提交`、`回滚`。
- **要点**：这是 dbx 布局最值得学的部分——**作用域明确的按钮贴着作用域放**，用户永远不需要猜"这个按钮会影响什么"。写操作（提交/回滚）与读操作（刷新）同排但视觉等权，靠位置（右端）而非颜色区分。

### ③'' 数据网格

- 行高极小（约 24px），字号 12px，等宽数字；斑马纹极淡或无。
- 列头 = `图标 + 列名 + 类型小字(varchar(16)) + 排序箭头 + 筛选入口`，一列的全部交互收敛在列头。
- 行首固定 `#` 序号列，横向滚动时冻结。
- 长文本不换行，截断 + 点击查看，撑爆行高。
- **要点**：数据工具的颜值来自"一行能看尽可能多的信息"，而不是留白。

### ⑤ 底部状态条

- 一行 24px：`共100行(统计总行数) 7ms` | 当前 SQL | `100行/页` | `« ‹ 1 › »` | `导出 ▾`。
- **要点**：把"系统在干什么"（耗时、SQL、分页）常驻可见，替代弹 toast。

### ④ AI 助手侧栏（右栏）

- 结构自上而下：**对话流（markdown 富渲染：标题/表格/代码块/加粗）→ 快捷回复按钮（`✓ 是，请继续` `× 不用了`）→ 上下文选择器（`31-mysql ▾ / test200 ▾`）→ 模型选择器 → 输入框（`输入@可选择表或SQL文件`）**。
- 关键交互：
  1. **AI 需要确认时，把确认做成对话流内的按钮**，而不是模态弹窗——不打断、可忽略、留痕。
  2. **上下文选择器常驻输入框上方**，用户清楚"AI 现在看着哪个库/表"。
  3. 回答中的结构化数据（如统计表）用真实表格渲染，不是纯文本。
- **要点**：这是与 InfraDeck AI Panel 最直接对标的部分，核心思想是 **approval 是对话的一部分，不是系统的 modal**。

## 3. 设计法则提炼（可直接当评审 checklist）

| # | 法则 | dbx 证据 |
| --- | --- | --- |
| L1 | 单窗口完成一切，功能靠分区不靠弹窗 | 提交/回滚/传输/AI 全在主窗 |
| L2 | 按钮贴着它的作用域：全局动作→顶栏，数据集动作→网格工具条，节点动作→树 hover | 三层工具条各管各的 |
| L3 | 密度优先：小字号(12px)、小行高(24px)、细边框(1px #eee)，信息量优先于留白 | 网格与树 |
| L4 | 颜色只用于分类与状态，不用于装饰 | 表/视图图标色、连接状态点、state 徽标 |
| L5 | 低频功能全部折叠（`更多▾`、hover 显示），常驻区域只留高频 | 顶栏、树节点 |
| L6 | 状态常驻可见（tab 存活点、底部状态条），替代 toast/弹窗 | ②⑤ |
| L7 | 多上下文用 tab 并存，切换=点击 | ② |
| L8 | AI 确认内联在对话流里（按钮式 approval），上下文选择器常驻 | ④ |
| L9 | 结构化输出用真实组件渲染（表格/代码块），不用纯文本 | ④ markdown 渲染 |

## 4. 映射到 InfraDeck：现状 vs 建议改版

InfraDeck 现有三栏（ServerSidebar / 主区 终端·文件·容器 / AI Panel）骨架与 dbx 同构，差距在密度、按钮归置和 AI 内联确认。按 L1–L9 逐条对照：

### 4.1 已经对齐的

- 三栏分区、右栏 AI Panel、左栏服务器清单（L1、L8 骨架已存在）。
- 主区 `终端 | 文件 | 容器` 视图切换 ≈ dbx 的 tab 语义（但见 4.2-②）。

### 4.2 建议改版清单（按投入产出排序）

| 优先 | 改版项 | 现状 | 对应法则 | 具体做法 |
| --- | --- | --- | --- | --- |
| P0 | **审批内联化** | 工具审批是 modal 弹窗（userApproval 卡片），打断操作 | L8 | 审批卡改为 AI Panel 对话流内的内联卡片 + `批准/拒绝` 快捷按钮；主区顶部仅在有待审批时显示一条细提示（可点击跳到审批卡） |
| P0 | **AI 上下文选择器常驻** | AiPanel 有 context badge，但不随输入框、不可切换 | L8 | 输入框上方常驻 `服务器 ▾ / 目录或容器 ▾` 面包屑选择器，与 fs/docker 工具的 target 联动 |
| P1 | **主区工具条归置** | 文件视图工具条（上传/新建目录/刷新）与 AI 动作混杂；容器视图工具条尚可 | L2 | 每个视图一条贴边工具条，只放作用于当前视图的动作：文件=路径面包屑+新建目录+上传+刷新；容器=显示已停止+刷新；终端=新建 tab+关闭。AI 命令入口统一收进命令面板（⌘K），不占工具条 |
| P1 | **密度提升** | 现有 12px 类似，但行高、间距偏松（file-row padding 6px 9px 尚可，容器/审批卡偏大） | L3 | 统一 token：`--row-h: 26px; --font-ui: 12px; --font-mono: 11px; 边框 1px`；文件/容器/审计行统一到同一套行组件样式 |
| P1 | **会话 Tab 化** | 终端已有 TerminalTabs，但文件/容器视图不随 tab 走，视图是全局单例 | L7 | 把 tab 提升为"服务器会话"级：每个 tab 内含 终端/文件/容器 子视图，切换服务器=切 tab（与 dbx 连接 tab 同构） |
| P2 | **状态常驻条** | 连接状态在侧栏节点上；传输在队列条；无全局状态条 | L6 | 主区底部加 24px 状态条：当前服务器@环境徽标 · 连接状态点 · 活跃传输数 · 最近工具结果耗时 |
| P2 | **左侧树增强** | 侧栏是平铺服务器列表，无层级、无搜索 | L3/L5 | 服务器 → 目录常用路径收藏 → 容器分组，加过滤搜索框；hover 显示连接/断开按钮 |
| P2 | **结构化渲染 AI 结果** | tool result 以摘要文本 + code 展示 | L9 | AI Panel 里 tool result 按返回类型渲染：fs.list → 迷你表格，docker.ps → 表格，fs.read → 代码块 |

### 4.3 设计 token 草案（供 styles.css 迁移）

```
字号：   UI 12px / 等宽 11px / 区块标题 12px semibold（不用大标题）
行高：   列表行 26px / 工具条 32px / 顶栏 38px / 状态条 24px
间距：   区块间 8px / 行内 gap 8px / 工具条 padding 4px 8px
边框：   全部 1px，分区用边框不用阴影
圆角：   控件 6px / 容器 9px（维持现状）
颜色：   语义色只用于状态徽标（沿用 M10 的 state-badge 配色）；
        主题维持暗色，但对照 dbx 浅色密度重排间距
图标：   每类资源一个实心小图标 + 颜色（服务器/目录/文件/容器/服务/进程）
```

### 4.4 明确不照搬的

- dbx 的浅色主题、macOS 一体化顶栏：InfraDeck 是运维工具，暗色 + 独立标题栏更合适。
- dbx 把 AI 放右栏且可整体收起——InfraDeck 的 AI 是一等公民，保持常驻，但审批内联后右栏宽度可从固定值改为可拖拽。

## 5. 落地切分建议（若立项）

- **批次 A（P0，纯前端，~1 天）**：审批内联化 + AI 上下文选择器 + 密度 token 统一。
- **批次 B（P1，~1–2 天）**：各视图工具条归置 + 会话 Tab 化（动 App.tsx 状态结构，需回归终端重连逻辑）。
- **批次 C（P2）**：状态条 + 左侧树增强 + AI 结构化渲染。

批次 A 不动状态结构，可独立验证；批次 B 触及 tabs/connections 状态，建议单独立项走 V1.2 文档流程。
